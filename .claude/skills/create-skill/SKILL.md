# Create Skill

요구사항을 파악하고, 기존 스킬을 확인한 뒤, 필요하면 SKILL.md 형식의 새 스킬을 작성합니다.

## When to Use This Skill

- "~하는 스킬 만들어줘", "스킬 제작", "새 스킬 작성"처럼 스킬 자체를 만들어 달라고 할 때
- 반복되는 작업 절차를 스킬로 정리하고 싶을 때
- 기존 스킬을 참고해 사용자 프로젝트에 맞게 변형하고 싶을 때

## Step 1: 요구사항 파악

다음을 확인합니다. 빠진 정보가 있으면 한 번에 묶어서 질문합니다.

1. 어떤 작업을 자동화하거나 표준화할지 (도메인, 구체 작업)
2. 입력과 출력이 무엇인지 (예: 파일 경로, 생성될 문서 형식)
3. 어떤 상황에서 발동되어야 하는지 (사용자가 쓸 법한 문장 예시)
4. 외부 명령, 파일 수정, 삭제 등 부작용이 있는지
5. 적용 범위: 이 프로젝트만 (`.claude/skills/`) 또는 모든 프로젝트 (`~/.claude/skills/`)

## Step 2: 기존 스킬 확인

새로 만들기 전에 이미 있는 스킬을 찾습니다.

```bash
npx skills find <query>
```

- 설치량 1K 이상, `vercel-labs`, `anthropics` 같은 공식 출처를 우선합니다.
- 적합한 스킬이 있으면 설치 명령을 제안하고, 사용자가 직접 만들기를 원할 때만 다음 단계로 갑니다.

## Step 3: 이름과 위치 정하기

- 이름은 소문자 kebab-case를 씁니다. 예: `pdf-summary`, `release-notes`
- 폴더 이름과 frontmatter의 `name`을 똑같이 맞춥니다.
- 위치:
  - 프로젝트 전용: `<프로젝트>/.claude/skills/<name>/SKILL.md`
  - 전역: `~/.claude/skills/<name>/SKILL.md`
- 같은 이름의 폴더가 이미 있으면 덮어쓰지 말고 사용자에게 확인합니다.

## Step 4: SKILL.md 작성

파일은 다음 구조를 따릅니다.

```markdown
---
name: <kebab-case-name>
description: <무엇을 하는지 + 언제 쓰는지 트리거 문구 1~3문장>
---

# <스킬 제목>

<한 줄 개요>

## When to Use This Skill
- <발동 상황>

## Step 1: ...
<구체적인 절차. 명령, 경로, 판단 기준을 적습니다>

## Examples
<입력 예시와 기대 결과>

## Notes
<주의사항, 하지 말아야 할 것, 막혔을 때 처리>
```

작성 원칙:

- `description`은 모델이 이 스킬을 고를지 결정하는 유일한 근거입니다. 무엇을 하는지와 어떤 말에 반응하는지를 모두 넣습니다.
- Claude가 이미 아는 일반 지식은 적지 않습니다. 이 프로젝트나 이 작업에만 필요한 정보를 적습니다.
- 절차는 실행 가능한 형태로 씁니다. 실제 명령, 실제 경로, 판단 기준을 적습니다.
- 파일 삭제, 외부 전송, 패키지 설치처럼 되돌리기 어려운 동작은 실행 전에 사용자 확인 단계를 넣습니다.

## Step 5: 검증

1. 파일 맨 위가 `---`로 시작하고, `name`과 `description`이 모두 있는지 확인합니다.
2. 폴더 이름과 `name`이 일치하는지 확인합니다.
3. `/skills` 명령으로 목록에 나타나는지 확인합니다.
4. 트리거 문장 한두 개로 스킬이 실제로 선택되는지 시험합니다. 선택되지 않으면 `description`을 더 구체적으로 고칩니다.

## Step 6: 완료 보고

다음을 짧게 알려줍니다.

- 생성한 파일 경로
- 발동되는 문장 예시
- 사용 방법
- 아직 확인하지 못한 부분 (예: 새 세션에서 트리거 미확인)

## Notes

- 스킬은 실행 권한을 가진 에이전트 지침입니다. 외부에서 받은 스킬은 내용을 읽고 설치하세요.
- 스킬 하나에 여러 목적을 넣지 말고, 목적이 하나인 작은 스킬로 나눕니다.
